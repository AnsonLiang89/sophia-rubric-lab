## 代码加固：防 dev 构建污染（2026-06-04 下午，根因订正）

承接上面的排障，做了三件根因加固 + 一次关键订正：

- **关键订正（务必记住）**：dev 构建污染的真凶是**环境变量 `NODE_ENV=development`**，不是缺 `--mode`。实测：
  - `vite build --mode production` 在 `NODE_ENV=development` 下**仍产出 dev 产物**（`fileName:` 痕迹=5）——`--mode` 压不住 `NODE_ENV`！这是我一开始改错的方向。
  - 只有 `NODE_ENV=production vite build` 才能强制干净构建（`fileName:`=0），即便环境被 `NODE_ENV=development` 污染。
- **修复1（package.json）**：`build` 与 `build:public` 的 vite build 一律加 `NODE_ENV=production` 前缀（不是 `--mode production`）。CI deploy.yml 走 `npm run build:public`，自动获得该保证、无需改。
- **修复2（运行时自检 src/lib/dataSource.ts）**：新增纯函数 `buildModeAnomaly(isDevBuild,hasHmr)` + 运行时包装 `detectBuildModeAnomaly()`。指纹=`import.meta.env.DEV && !import.meta.hot`（dev 构建但无 HMR 通道=dev 产物被静态托管），零误报。App.tsx init 时调用，命中则 `console.error`，把"靠肉眼发现数据缺失"变成"控制台显式报错"。
- **修复3（App.tsx）**：prod 只读版加载后若 products/queries 仍为空，`console.error` 提示 bundle 没烤或 404。
- **测试**：tests/dataSource.test.ts 加 `buildModeAnomaly` 四组合单测（153 测试全过）。
- **回归**：eslint✅ + tsc✅ + npm test 153/153✅ + `NODE_ENV=development npm run build:public`（污染环境）产物 `fileName:`=0✅ + agent-browser 实地总览「9 产品 11 题 10 完成」✅。
- **二次教训**：`--mode` 与 `NODE_ENV` 是两套独立开关，vite/esbuild 的 dev 注入看的是 `NODE_ENV`。要确保生产构建，**必须显式 `NODE_ENV=production`**，不能只靠 `--mode production`。验证构建是否纯净的探针：产物里 `grep -c "fileName:"` 应为 0。

## 排障：preview(4173) 页面只显示 seed(2产品/1题) — dev 模式构建污染

- 现象：`vite preview`(4173) 页面显示「SophiaAI v4 · 2 产品 · 1 题 · 0 完成」，但 curl 其 `/data/public-bundle.json` 是完整 9 产品。用户坚称 4173 数据缺失。
- 用 agent-browser 实地排查（不能只 curl）：页面内 `fetch('/data/public-bundle.json')` 能拿到 9 产品 11 题，但 store 渲染的是 localStorage 里的 seed（key `sophia-rubric-lab:v1`，含 sophia-v4+mirothink+EV-0001）。
- **根因**：dist 是 **dev 模式构建**的——产物里有 JSX dev 注入痕迹 `fileName:/lineNumber:`、页面有 React DevTools 提示、`@vite/client` 虽无但 `import.meta.env.PROD` 被编成 false。导致 `IS_READONLY=import.meta.env.PROD=false` → storage 选了 LocalAdapter 读 localStorage seed，而非 PublicBundleAdapter 读 bundle。dist/index.html mtime 15:01 也证明被某进程用非 prod 方式重建过。
- **修复**：`rm -rf dist && npx vite build`（vite build 默认 production）。新产物 `fileName:` 归零、store 里不再含 `sophia-rubric-lab:v1`、PublicBundleAdapter 生效。data 由 vite 从 `public/data/` 自动拷贝（含 kkv4）。重启 `vite preview --port 4173`。
- **验证**（agent-browser 实地）：总览「SophiaAI v10 · 9 产品 · 11 题 · 10 完成」✅；EV-0012 详情页 v10/kkv4/Gemini + 8.7/8.0 分数 + 评级齐全 ✅。
- **教训**：① 前端「数据缺失」类问题必须用浏览器实地看渲染，不能只 curl 数据层。② 判断 dist 是否 prod 构建：搜 `fileName:`(dev JSX 痕迹) 与 localStorage key 是否进 store 产物。③ prod 只读版靠 `import.meta.env.PROD` 切 PublicBundleAdapter，dev 构建会让它退化成读 localStorage seed。
