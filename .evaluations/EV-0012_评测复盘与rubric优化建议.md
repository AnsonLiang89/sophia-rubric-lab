# EV-0012 两轮评测复盘 · Rubric 与评测方法优化建议

> 评测官 Sophia｜复盘日期 2026-06-03｜基于 EV-0012 v1（首轮）与 v2（综合复评）的完整过程
> 性质：**方法论复盘 + 优化建议**，不改动任何契约/标准基线文件（基线变更属破坏性动作，留 Anson 拍板）

---

## 〇、一句话结论

两轮评测的排名骨架是稳的（v10🏆 始终第一，Gemini 始终末位），**唯一的实质变化是 Kimi 从 7.2「优秀」降到 6.9「合格」**。这个变化不是因为发现了新事实，而是因为**第二轮才补上了一个第一轮 rubric 没有强制评测官去看的视角——"信息密度 / 决策信噪比"**。

这恰恰暴露了当前 rubric 的核心短板：**它能很好地抓"对不对"（R1 事实纪律已经很硬），但对"答得准不准（子问题颗粒度）"和"帮不帮得上（信噪比）"两件事，缺少强制结构，全靠评测官当轮的临场意识。** 这就是为什么同一份报告，换个提示视角，结论会摆动。

## 一、两轮评测差异的精确刻画

### 1.1 档位变化（唯一差异）

| 产品 | v1 总分 | v2 总分 | 唯一变动维度 | 变动方向 |
|---|---|---|---|---|
| SophiaAI v10 | 8.7 卓越 | 8.7 卓越 | — | 不变 |
| Manus | 7.8 优秀 | 7.8 优秀 | — | 不变 |
| SophiaAI v5 | 7.2 优秀 | 7.2 优秀 | — | 不变 |
| **Kimi** | **7.2 优秀** | **6.9 合格** | **R5：A(8)→B(6)** | ⬇ 降档 |
| MiroThink | 6.0 合格 | 6.0 合格 | — | 不变 |
| Gemini | 5.4 待改进 | 5.4 待改进 | — | 不变 |

### 1.2 这个变化"是从哪来的"

- **不是新证据**：Kimi 那几处无源拟真数字（iPhone 2.5亿片 / 良率98.7% / GB300~5000电感），v1 就已经核到 inconclusive 并写进了 claimChecks。事实层认知两轮完全一致。
- **是新视角**：v1 给 Kimi R5=A 的理由是「投资关注要点分上中下游，take-away 可操作」——评测官只看了"有没有 take-away"，没看"这些 take-away 埋在 54907 字里、且无 caveat、用户要花多大成本才能甄别"。v2 在用户点明"有效辅助决策 vs 堆字数"后，才把"信噪比/诚实度"这一轴纳入 R5 评判，于是降档。

### 1.3 关键事实：篇幅与决策价值是负相关的

| 产品 | 篇幅(字) | v2 决策价值档(R5) | 信噪比裁决 |
|---|---|---|---|
| Kimi | **54907（最长）** | B | 长而难甄别 |
| SophiaAI v5 | 37439 | A | 长但有审计层 |
| SophiaAI v10 | 22002 | **S（最高）** | 短而可决策 |
| Manus | **12678（最短）** | A | 最精炼、口径诚实 |

**全场最短的 Manus 决策价值（A）高于全场最长的 Kimi（B）。** 这是"堆字数 ≠ 帮决策"的硬证据，但 v1 的 rubric 没有任何机制逼评测官看这张表——这是方法论缺口，不是评测官失误。

## 二、复盘：当前 Rubric / 方法论的三个结构性短板

### 短板 A：R2「相关性」对多子问题 query 缺少"子问题 × 产品"强制矩阵

**现象**：EV-0012 的 query 是典型 info-mining，内含 **8 个子问题**（应用/市场/格局/国产化率/未来量级/是否唯一/并行方案/壁垒）。v1 评测里，R2 我直接给 v10/v5/Kimi/Manus 全打 A，理由都是笼统的"八问全覆盖"——**但"全覆盖"和"每一问都答得好"是两回事**。直到 v2 我才被迫拉出「八子问题 × 六产品」覆盖矩阵，才发现 Gemini 在"国产化率/未来量级"两问其实是🔶偏薄、Miro 在三问偏粗。

**根因**：R2 的 checklist 第 1 项只说"列出 query 的核心诉求（≥1 条）和锚点"，**没有要求把复合 query 机械拆成子问题清单，再逐子问题 × 逐产品判定**。当 query 只有 1 个诉求时这没问题，但面对 8 子问题的 info-mining query，"≥1 条"的下限让评测官可以偷懒。

**后果**：R2 区分度被压平（4 个产品全 A），无法回答你最关心的"同一子问题下谁答得更好"。

---

### 短板 B：R5「决策价值」缺少"信息密度 / 信噪比"的负向锚点

**现象**：见 1.2/1.3。Kimi 用最长篇幅承载最难甄别的信息，v1 却给了 R5=A。

**根因**：R5 双轴里纵轴是"可操作性 + 诚实度"，**但"篇幅膨胀稀释决策价值"从来没被写进 checklist 或反例**。R5 的 5 条 checklist 全是"有没有 take-away / 有没有新框架 / 有没有 caveat"的**正向加分项**，没有一条是"是否存在信息冗余 / 读者甄别成本过高"的**负向扣分项**。评测官于是默认"内容多 = 价值高"，恰好踩反。

**更深一层**：这其实是 **R4（完备性）与 R5（决策价值）的张力没理清**。Kimi 数据丰富，在 R4 拿 A 是对的（维度全、表格多）；但同一份丰富度，在 R5 若无法甄别真伪、且推高阅读成本，反而应当减分。**"完备"和"有决策价值"被当成了同向指标，实际在长报告上是反向的。**

---

### 短板 C：R3「非共识」缺少跨产品横向归集，差异化贡献无法对比

**现象**：你的关注点③是"差异化/非共识观点的发现"。v1 里我只在 crossProductInsights 中体现了 v10 的非共识，**没有对每个产品系统扫一遍"它贡献了哪些差异化观点、带没带证据"**。v2 才补出「差异化非共识汇总表」，一对比就清楚：只有 v10 把非共识用在了"反转主流投资共识"上，其余多是技术层或共识梳理。

**根因**：R3 checklist 第 3 项问"是否出现非共识但有据的观点"，是**单产品 yes/no 判定**，没有要求"跨产品归集 + 决策增量排序"。导致"谁的非共识更值钱"这个对横评最关键的问题，在结构化字段里无处落脚（crossProductInsights 只聚焦 Sophia，非 Sophia 产品之间的非共识对比是盲区）。

## 三、优化建议（按优先级 + 可执行性排序）

> 原则：所有建议都遵循你既有的工程偏好——**能被 lint 机器校验 > 靠评测官自觉**；**先加结构约束，不动权重基线**（权重 40/15/20/10/15 是 v2 以来的稳定共识，不轻易碰）。

### P0 建议 1：新增 `summary.queryCoverageMatrix`（子问题 × 产品覆盖矩阵）——直击你的关注点①

- **做什么**：对 `type=info-mining` 或 prompt 含明显多子问题的 query，强制评测官先把 query 拆成子问题清单（Q1…Qn），再对每个产品逐子问题打 `✅ / 🔶 / ❌` 三档，连同一句话理由落进结构化字段。
- **为什么**：把"八问全覆盖=A"这种偷懒路径堵死，强制颗粒度下沉到子问题级，R2 才能产生真正的区分度。
- **lint 可校验**：子问题数 ≥2 时该字段必填；每个产品必须覆盖全部子问题；正文第二段必须渲染该矩阵。
- **契约落点**：新增 §3.13；R2 checklist 第 1 项改为"复合 query 必须拆子问题并逐项判定"。

### P0 建议 2：R5 增加"信息密度 / 信噪比"负向 checklist 项 + 反例——直击你的关注点②

- **做什么**：R5 必查 checklist 从 5 项扩到 6 项，新增第 6 项：**"是否存在信息冗余 / 篇幅膨胀稀释决策价值？读者甄别有效信息的成本是否过高？"**；并在"典型反例（自动扣档）"里加一条：**"用远超必要的篇幅承载大量无源/难核信息，迫使读者承担高甄别成本——信噪比低，R5 封 B 上限"**。
- **为什么**：把这次靠用户提示才补上的视角，固化成 rubric 的常驻检查项，下一轮评测官无需提示也会看。
- **配套**：在 R5 双轴判定表的纵轴"诚实度"语义里补一句"长报告零 caveat = 诚实度轴下移一档"。
- **契约落点**：RUBRIC_STANDARD.md R5 小节。

### P1 建议 3：R3 非共识做成"跨产品差异化贡献归集表"

- **做什么**：R3 checklist 增加"跨产品归集"要求——逐产品列出其差异化/非共识观点、是否带 why 三联、决策增量高/中/低，形成一张全产品对比表（不只聚焦 Sophia）。
- **为什么**：让"谁的非共识更值钱"有结构化落点，直接服务横评的核心目的。
- **可选增强**：crossProductInsights 增加一个 `nonConsensusLeaderboard` 子字段，记录本轮非共识贡献排名。

### P1 建议 4：把"阅读成本 / 信息密度"提升为 info-mining 类的**默认建议激活扩展维度**

- **做什么**：扩展维度词表里"阅读成本"已存在但从未被激活。建议对 info-mining 长报告横评，**默认建议激活"信息密度"扩展维度（权重 0.05）**，与 R5 形成"决策价值看质、信息密度看效率"的互补。
- **为什么**：R5 改 checklist 是定性兜底；激活扩展维度是定量显性化。两者可二选一或并用。
- **注意**：这会触发 R1~R5 等比缩减，属权重层改动，**优先级低于建议 1/2**，可作为观察项先不激活、只在 report 里讨论。

### P2 建议 5：把"评测稳定性"写进方法论自检

- **做什么**：history-gate 阶段（v3.6 已有）补一条自检：**"本轮与上一版的档位差异，是源于新证据，还是源于评测视角变化？若是后者，说明上一版的 rubric 覆盖存在盲区，应在复盘中记录该盲区。"**
- **为什么**：这次 Kimi 降档本质是"上一版漏看了一个维度"。把这种"非证据驱动的摆动"显式标记出来，能持续暴露 rubric 盲区，形成自我改进闭环。这正是 deltaReason 字段更深一层的用法。

## 四、不建议动的部分（避免过度设计）

为防止"为优化而优化"，明确几条**保持不变**：

1. **权重 40/15/20/10/15 不动**：这是 v2 以来的稳定共识，两轮评测没有任何证据表明权重错配。Kimi 的问题是 R5 判定标准缺项，不是 R5 权重太低。
2. **5 档制 / tier 先定 score 后映射不动**：机械映射是反向凑分的有效防线，运行良好。
3. **一票否决 V1~V5 不动**：EV-0012 里"MPP 占比错但不触发 veto"的判定是正确的（占比错≠量级错），说明 V1~V5 的边界是清晰的，不需要扩列。
4. **factCoverageMatrix（T1~T8）不动**：事实类型扫描机制本轮运转良好（铌正确、MPP 证伪都是它抓出来的），不要和新增的 queryCoverageMatrix 混淆——一个管"事实对不对"，一个管"子问题答没答"，正交互补。

## 五、落地路线建议（如果你决定采纳）

| 阶段 | 动作 | 影响面 | 风险 |
|---|---|---|---|
| 第一步 | 建议 1 + 建议 2（加结构 / 加 checklist，**不动权重**） | 契约 +§3.13、标准 R2/R5 小节、lint 加两条校验 | 低：纯增量，历史产物走 legacy grandfather 不受影响 |
| 第二步 | 建议 3（R3 归集表） | 标准 R3 小节、crossProductInsights 可选子字段 | 低 |
| 第三步 | 建议 5（稳定性自检） | history-gate 文案 | 极低 |
| 暂缓 | 建议 4（激活信息密度扩展维度） | 触及权重缩减 | 中：先观察，攒 2-3 轮 info-mining 案例再定 |

**契约版本语义**：建议 1+2+3+5 属"评测语义增强"，落地时应升 contractVersion 到 **3.7**，旧产物保留原版本号（沿用 §6.2 不迁移 + 已有的 legacy grandfather 机制）。

> 复盘核心收获：**这次 Kimi 降档不是评测出错，而是评测方法的一次"自暴露"——rubric 在"子问题颗粒度"和"信噪比"上的盲区，被一次视角切换照了出来。把这两个盲区从"靠提示"变成"靠结构+lint"，是本轮复盘最有价值的产出。**
